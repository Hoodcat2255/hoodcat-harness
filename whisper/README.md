# whisper-local

유튜브 영상 또는 로컬 음원·영상을 **faster-whisper large-v3**로 전사한다. 그다음 **설명란·유튜브 자막·화면 텍스트(OCR)·영상 프레임**을 근거로 Claude가 교정하고, 필요하면 요약한다.

## 사용법

```bash
# 전체: 다운로드 → 용어집 → 전사 → 교정 → 프레임 분석 → 문서 (형식은 영상 성격으로 자동 판별)
uv run transcribe.py "https://www.youtube.com/watch?v=VIDEO_ID" --summarize

# 화면 텍스트 OCR까지 (자막·이름표의 고유명사로 교정, CPU라 영상 길이만큼 더 걸린다)
uv run transcribe.py URL --summarize --ocr

# 문서 형식 지정: summary(요약) / outline(정리) / notes(학습 노트)
uv run transcribe.py URL --summarize --mode notes

# 전사만 (Claude 호출 없음)
uv run transcribe.py URL --asr-only

# 영상·화면 분석 없이 (음원 + 메타데이터 + 자막만)
uv run transcribe.py URL --no-video

# 로컬 파일 (영상 파일이면 프레임 분석도 수행, OCR은 --ocr)
uv run transcribe.py lecture.mp4 --language en
```

결과물은 `output/<영상ID>/`에 생긴다. 단계별 결과를 캐시하므로 다시 실행하면 끝난 단계는 건너뛴다.

| 파일 | 내용 |
|---|---|
| `transcript.md` | **최종본**: 타임스탬프와 교정된 전사, `> [화면 …]` 화면 설명 |
| `transcript.txt` / `.srt` | 교정된 전사 (텍스트 / 자막) |
| `corrections.json` | 모든 교정 제안과 근거, 적용 여부 (`applied` / `skipped: …`) |
| `<mode>.md` | 결과 문서 (`summary.md` / `outline.md` / `notes.md`). 설명에 필요한 영상 프레임이 `<mode>_images/`를 참조하는 이미지로 들어간다 |
| `<mode>.html` | 같은 문서를 이미지까지 넣은 단일 HTML. 파일 하나로 브라우저에서 열거나 전달할 수 있다 |
| `<mode>.pdf` | `--pdf`를 주면 같은 문서를 A4 PDF로 저장한다 (Chrome headless로 출력, 한글 글꼴과 이미지 포함). 이미 만든 문서는 캐시를 쓰므로 Claude 호출 없이 PDF만 만든다 |
| `classify.json` | `--mode auto`일 때 영상 성격 판별 결과 |
| `asr.json` | Whisper 원본 결과와 사용한 옵션 (hotwords 등) |
| `ocr.json`, `glossary.json`, `correct.json`, `visual.json` | 단계별 중간 결과 |
| `audio.m4a`, `video.mp4`, `info.json`, `subs.*.vtt`, `frames/`, `visual/` | 원자료 |

## 녹음 파일 (회의·인터뷰·강의 녹음·통화·음성메모)

```bash
uv run transcribe.py 회의.m4a --summarize \
  --context "3분기 예산 회의, 영업팀" --speakers "김민수,이지은" --terms "OKR,하이브리드 근무"
```

- 오디오만 있는 파일은 자동으로 **녹음**으로 처리한다. 영상 파일을 녹음으로 다루려면 `--source-kind recording`을 준다.
- 문서 형식은 `meeting`(회의록: 결정 사항·할 일 표), `interview`(질문과 답, 주목할 발언), `notes`(강의), `memo`(할 일 체크리스트), `summary` 중에서 자동으로 고른다.
- 녹음에는 설명란과 자막이 없다. 그래서 `--context`·`--terms`·`--speakers`가 교정의 주요 근거가 된다 (근거 종류는 `user`).
- **화자 분리는 하지 않는다.** 참석자 명단과 문맥으로 분명할 때만 화자를 쓰고 '(추정)'을 붙인다. 이 GPU(6GB)에서 pyannote가 메모리 부족을 일으킬 가능성이 커서 검토 후 제외했다.
- **개인정보**: 녹음은 기본으로 전화번호·주민번호·계좌·카드번호·이메일을 Claude로 보내기 전에 `[전화번호]` 같은 표시로 바꾼다 (`--mask`). 가리기 전 원본은 로컬 `asr.json`에만 남는다. 숫자를 한글로 받아 적은 경우("공일공…")는 잡지 못한다.
- 녹음은 분석 섹션과 사실 확인을 기본으로 하지 않는다 (`--analysis on`으로 켠다).
- **긴 녹음**: 한국어 발화는 분당 약 300~350자다. 전사가 2만 자(약 1시간)를 넘으면 15분 단위로 나눠 교정한다. 5만 자(약 2시간 반)를 넘으면 구간 노트로 압축한 뒤 문서를 만든다. 69분 주민설명회에서 두 경로를 모두 확인했다 (문서 분할은 기준을 낮춰 시험).
- Claude Code에서는 `recording-notes` 스킬로 쓸 수 있다 (`~/.claude/skills/recording-notes/`).

## 파이프라인

| 단계 | 내용 | 비용 |
|---|---|---|
| 1. fetch | yt-dlp로 음원, 720p 영상, info.json, 업로더 수동 자막과 자동자막을 받는다 | – |
| 2. ocr (`--ocr`) | 기본은 건너뛴다. 3초 간격 프레임을 뽑아 중복을 제거하고, RapidOCR(PP-OCRv5 한국어)로 읽는다. 로고처럼 계속 떠 있는 텍스트는 제외한다 | CPU, 프레임당 약 3초 (표가 가득한 화면은 6초 이상). 18분 강연은 약 15분 |
| 3. glossary | 설명란·태그·OCR에서 고유명사·전문용어를 뽑아 교정 단계에 표기 참고 자료로 준다 (Whisper 힌트로는 쓰지 않는다, 아래 주의 참고) | Claude haiku 1회 |
| 4. asr | faster-whisper large-v3, int8_float16, 15초 조각, 단어 타임스탬프. 환각 출력은 버리고 4b로 넘긴다: 세그먼트 안 단어 반복, 같은 문장이 세그먼트 3개 이상 연속(6자 미만 맞장구는 제외), 깨진 문자(`�`)·자막 크레딧(`Amara.org`, `Sous-titr`)·한국어 전사의 한자 2자 이상 | GPU (OOM이면 CPU) |
| 4b. 누락 재전사 | VAD로는 말소리인데 어떤 단어도 인식되지 않은 구간(1.5초 이상)을 그 부분만 잘라 다시 전사한다. 글자 밀도가 초당 2자 미만이거나 크레딧 문구가 있으면 버린다. `transcript.md`에 `(재전사)`로 표시한다. 끝나면 VAD 발화 시간 대비 단어가 덮은 비율(커버리지)을 로그와 `asr.json` meta에 남기고, 90% 미만이면 경고한다 | GPU |
| 5. correct | Claude 교정 (아래 규칙) | Claude 1회 |
| 6. visual | 화면을 봐야 하는 발화(최대 12개)의 프레임을 Claude가 직접 보고 설명·교정한다 | Claude 1회, 이미지 1장당 약 1.2k 토큰 |
| 7. document | 영상 성격을 판별해(haiku) 요약·정리·학습 노트 중 하나로 문서를 만든다. 화면 분석 프레임과 판서·슬라이드 OCR 프레임(`--ocr`일 때)을 후보로 주면, Claude가 필요한 곳에 최대 8장을 넣는다. 후보에 없는 경로는 코드가 지운다 | Claude 1회 (이미지는 설명만 전달해서 추가 비용이 거의 없다) |

### 교정 규칙 (환각·과잉 교정 방지)

- 발화를 다시 쓰지 않는다. **세그먼트에 글자 그대로 있는 부분 문자열(`before`)만** 바꾸며, 일치하지 않으면 적용하지 않고 기록만 남긴다.
- 모든 수정에 근거 종류와 원문 인용을 남긴다. 근거 우선순위는 `description` > `youtube_manual` > `ocr`·`frame` > `youtube_auto` > `context`이다.
- 누락 복원(insertion)은 설명란 원고나 유튜브 자막에 근거가 있을 때만 한다. `transcript.md`에 `(복원)`으로 표시한다.
- 환각 삭제는 자막에도 근거가 없는 정형 문구("다음 영상에서 만나요" 등)에만 한다.
- 숫자는 문맥(`context`)만으로 고치지 않는다. 코드도 숫자를 바꾸는 `context` 교정은 `skipped`로 남긴다.
- 숫자 판독이 갈리는 줄은 `transcript.md`에 `(수치 확인 필요)`를 붙이고, 문서에서도 단정하지 않는다. 영상은 같은 시간대 유튜브 자막의 숫자와 다를 때, 녹음은 숫자 단어의 인식 확률이 0.5 미만일 때다.
  - 한계: 아라비아 숫자만 비교·차단한다("삼억 → 사억" 같은 한글 수사 교정은 프롬프트에만 의존). 녹음의 재전사 줄은 단어 확률이 없어 표시되지 않고, 근거 있는 교정으로 숫자를 이미 고친 줄에도 표시가 남을 수 있으며, `--asr-only`에서는 표시하지 않는다.
- 인물은 화면에 **쓰인 이름**으로만 특정한다. 얼굴로 식별하지 않는다.

## 문서 형식 (`--mode`)

| 형식 | 맞는 영상 | 구성 |
|---|---|---|
| `summary` 요약 | 뉴스, 시사, 인터뷰, 브이로그 | 한 줄 요약 / 핵심 / 세부 / 고유명사·수치 |
| `outline` 정리 | 강연, 설명 영상, 리뷰, 사용법 안내 | 전체 구조 / 섹션별 주장·근거·단계·비교표 / 실천 포인트 |
| `notes` 학습 노트 | 강의, 튜토리얼, 교육 | 학습 목표 / 핵심 개념 표 / 개념별 설명 / 요약 / 복습 문제와 정답 |
| `auto` (기본) | – | 제목·설명란·전사 앞부분으로 위 셋 중 하나를 고른다 |

### 분야 판별

`classify.json`의 `domain`(주 분야)과 `secondary_domains`(부 분야, 영상의 약 1/4 이상을 차지할 때만, 최대 2개)으로 분석 섹션을 붙일지와 분야별 점검 항목을 정한다. 판별 원칙은 '누가 등장하느냐가 아니라 무엇에 관한 내용인가'다.

판별 정확도는 다음과 같다 (`docs/eval-classify-unseen.md`).
- 처음 보는 영상 20개: 20/20. 이전 기준은 19/20이었다.
- 기준 작성에 쓴 영상 20개: 20/20. 이전 기준은 18/20이었다.

### 분석 섹션 (`--analysis auto|on|off`)

정치·경제 영상이면(판별 결과 `domain`) 문서 끝에 **"분석 — Claude의 의견 (영상 내용 아님)"** 섹션을 붙인다. 요약과 섞이지 않도록 별도 호출로 만든다. `on`이면 분야와 상관없이 붙이고, `off`면 붙이지 않는다.

- 구성: 핵심 쟁점과 이해관계자 / 비판적 검토(근거 강도, 빠진 관점, 프레이밍) / 미래 전망(기본·낙관·비관 시나리오와 조건, 지켜볼 신호) / 확인이 필요한 부분
- **분야별 점검 항목**: 판별된 주·부 분야(정치·경제·사회·기술·과학·건강)의 체크리스트를 분석 프롬프트에 넣는다 (`ytscribe/llm.py`의 `DOMAIN_GUIDES`). 과학·건강은 시나리오형 전망 대신 "근거 수준과 추가로 필요한 근거"를 쓴다. 분야마다 에이전트를 따로 두지 않는다. 역할만 바꾸는 것은 정확도에 효과가 없다는 연구가 있고, 같은 문맥을 공유해야 하는 작업에 멀티에이전트는 비용만 키운다 (`docs/research-domain-agents-20261003.md`).
- **평가** (`eval/`, 결과 `docs/eval-domain-guides.md`): 6개 분야 영상 17개로 지침 없음(A)과 지침 포함(B)을 블라인드 LLM 채점했다. AB·BA 두 순서로 채점해 위치 편향을 보정했다.
  - 결과: B 13 / A 0 / 동률 4. 유용성은 4.15에서 4.88로, 점검 항목 반영도는 3.91에서 4.94로 올랐다.
  - 동률은 정치 2개와 기술 2개였다. 채점자는 나중에 제시된 쪽을 선호하는 편향을 보였다.
  - 한계: 채점자가 같은 모델 계열이다. 점검 항목 반영도는 지침을 아는 채점자 기준이라 B에 유리하다. 사람 평가는 하지 않았다.
- 규칙: 영상 밖 사실은 단정하지 않고 '추정'·'확인 필요'로 표시한다. 지식 시점의 한계를 밝힌다. 정치 주제는 주요 입장을 같은 무게로 다룬다. 투자·법률 조언처럼 쓰지 않는다.

### 사실 확인 (`--verify`)

분석 단계가 '확인이 필요한 부분' 중 웹으로 확인할 수 있는 주장을 최대 8개 뽑는다. 사실 확인 호출이 이 주장들을 WebSearch로 확인하고, 결과를 분석 섹션 끝에 표로 붙인다.

- 사실 확인 호출에는 **주장 목록만** 넘긴다. 영상 설명란과 전사 원문은 넘기지 않는다.
- 페이지 열기(WebFetch)는 `trusted_domains.txt`에 있는 도메인과 그 하위 도메인으로만 허용한다.
- 모델이 사실·다름·일부·변경으로 판정해도, 근거 URL이 신뢰 도메인에 없으면 코드가 `❔ 미확인`으로 낮춘다. 영상 설명란에 심은 지시로 공격자 페이지를 근거 삼는 '거짓 검증'을 막기 위함이다. WebSearch는 검색어와 결과 도메인을 권한으로 제한할 수 없다.
- 비용 상한은 `--verify-budget`이다 (기본 $1). 경제 영상 8개 주장 확인에 $0.45가 들었다.

Claude Code에서는 `youtube-digest` 스킬로 쓸 수 있다 (`~/.claude/skills/youtube-digest/`). 유튜브 링크와 함께 "요약해줘", "정리해줘", "노트 만들어줘"라고 하면 된다.

## 주요 옵션

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--model` | `large-v3` | `turbo`는 빠르지만 한국어 정확도가 낮다는 보고가 있다 |
| `--compute-type` | `int8_float16` | RTX 2060은 bfloat16 미지원. 테스트에서 float16과 정확도 차이가 없었다 |
| `--chunk-length` | `15` | 30이면 BGM이 깔린 인터뷰를 누락하고, 10이면 문장이 잘린다 |
| `--ocr` | 꺼짐 | 화면 텍스트 OCR을 교정·용어집 근거로 쓴다. 설명란·자막이 부실하고 화면 자막에 고유명사가 많을 때 |
| `--frame-interval` | `3` | OCR 프레임 간격(초). 자막이 빨리 바뀌는 예능은 2로 |
| `--max-images` / `--no-images` | `8` / – | 요약에 넣을 이미지 최대 수 / 이미지를 넣지 않는다 |
| `--max-visual` | `12` | Claude가 볼 프레임 수. 20을 넘기면 이미지 크기 제한이 엄격해진다 |
| `--hotwords`, `--prompt` | – | Whisper 힌트를 직접 지정한다. 기본은 없음 (아래 주의 참고) |
| `--force` / `--force-asr` | – | 모든 캐시를 무시한다 / 전사만 강제로 다시 한다 (보통은 입력 지문으로 자동 판단하므로 필요 없다) |

## 주의

- **Whisper에 자동 힌트(`initial_prompt`·`hotwords`)를 넣지 않는다.** 두 영상에서 비교한 결과다.

  | 영상 (기준) | 힌트 없음 | 제목을 `initial_prompt`로 | 용어집을 `hotwords`로 |
  |---|---|---|---|
  | KBS 리포트 (설명란 원고 대비 CER) | 0.205 | 0.373, 크레딧 환각 3건 ("영상편집 박진주") | 0.202 |
  | 전기 강의 (유튜브 자막 대비 CER) | **0.104** | – | 0.374, 반복 환각 8건 ("정전기 전병칠 정전기 전병칠…") |

  흔한 용어(전압, 전류)나 채널명을 `hotwords`로 넣으면 그 단어를 반복하는 루프에 빠진다. 용어집은 교정 단계에서만 쓴다. `--hotwords`는 드문 고유명사만 직접 지정할 때 쓴다.
- **ComfyUI와 GPU를 같이 쓴다.** ComfyUI가 생성 작업 중이면 VRAM을 최대 약 4.9GB 쓴다. 이때 OOM이 나면 자동으로 CPU(int8)로 전환하며, 실시간보다 약 2배 느리다.
- `av<19`로 고정한다. faster-whisper 1.2.1이 av 19에서 제거된 인자를 쓴다.
- PaddleOCR(paddlepaddle 3.3.1)은 CPU oneDNN 오류가 있고, 끄면 프레임당 18~42초가 걸려 RapidOCR(onnxruntime)로 대체했다. 방향 분류(cls)를 끄고 8스레드로 실행한다 (4.7초에서 3.2초/장으로 단축).
- **배경음악이 깔린 인터뷰 누락**: 배치 전사가 내레이션과 한 조각으로 묶으면 인터뷰를 통째로 빠뜨린다. 4b 단계가 대부분 복구하지만, 인터뷰 첫 2~3초처럼 짧은 조각은 단독으로도 인식되지 않는다. 이런 구간은 설명란 원고나 자막이 있으면 교정 단계가 `(복원)`으로 채운다.
- **프레임 분석 보안**: Claude는 `visual/` 디렉터리 안의 `*.jpg`만 읽을 수 있다 (`--allowedTools "Read(./*.jpg)"`, `--permission-mode dontAsk`, 사용자 설정 미로드). 설명란이나 화면 글자에 프롬프트 인젝션이 있어도 다른 파일을 읽지 못한다.
- **캐시**: 단계마다 입력 지문(옵션, 상위 단계 결과, 프롬프트)을 저장한다. 하나라도 바뀌면 그 단계와 이후 단계를 자동으로 다시 계산한다.
- YouTube가 반복 요청에 `HTTP 429`를 반환할 수 있다. 자막 다운로드는 실패해도 계속 진행한다.
- YouTube 약관은 허용되지 않은 다운로드를 금지한다. 개인 용도로만 쓰고 재배포하지 않는다.

## 설치 (재현용)

```bash
uv sync
uv run pytest -q   # 파서·교정 로직 단위 테스트
```

시스템 CUDA Toolkit은 필요 없다. pip로 받은 cuBLAS/cuDNN을 스크립트가 직접 로드한다. ffmpeg와 `claude` CLI는 시스템에 있어야 한다.

### macOS (Apple Silicon)

```bash
brew install uv ffmpeg
uv sync            # nvidia-* 대신 mlx-whisper가 설치된다
# PDF(--pdf)용: GUI 로그인 없이(SSH 등)도 동작하는 headless Chrome
npx @puppeteer/browsers install chrome-headless-shell@stable --path ~/.cache/chrome-headless-shell
```

- `--device auto`(기본)는 Apple Silicon에서 **mlx-whisper**(Metal GPU)를 쓴다. faster-whisper(CTranslate2)는 macOS에서 CPU로만 돈다.
- mlx 경로는 faster-whisper의 VAD로 발화 구간을 찾아 15초 이하 창으로 묶어 전사한다. 빔 서치와 `--hotwords`는 지원하지 않는다 (greedy 디코딩).
- greedy 디코딩은 창 끝 무음에서 짧은 환각("이 시각 세계였습니다.")을 만들 수 있어, 창 끝 0.2초 안에 붙은 단어 확률 평균 0.6 미만 세그먼트는 버린다. 실제 발화였다면 누락 재전사(4b)가 다시 다룬다.
- M4(16GB) 측정: 뉴스 3편(2~3분)에서 실시간 대비 약 3.5배. 리눅스 RTX 2060 결과와 글자 유사도 0.986.
