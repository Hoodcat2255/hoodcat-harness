# 이슈: 사용자 반박 미수용 패턴 — 1차 자료 검증 우선순위 부재

- **작성일**: 2026-05-16
- **상태**: Open (개선안 검토 대기)
- **영향 범위**: Main Agent, Orchestrator, Researcher (deepresearch 스킬 포함)
- **심각도**: High — 사용자 직관이 옳았음에도 에이전트가 반복적으로 잘못된 결론으로 유도, 사용자 시간 낭비 및 신뢰 저하 유발

---

## 1. 요약

에이전트(Main Agent / Orchestrator / Researcher)가 사용자의 직관적 반박을 받았을 때 다음과 같은 잘못된 행동 패턴이 반복적으로 관찰되었다:

1. 즉시 1차 자료(법령 원문, 공식 공고문, 정부 부처 고시 등)로 재검증하지 **않고**,
2. 추측 또는 2차 자료(블로그, 일반론, 언론 기사)에 근거하여 **반박부터 시도**한다.
3. 사용자가 2~4회 이상 push해야 비로소 `deepresearch` 스킬이 호출된다.
4. 최종 결과적으로 **사용자 직관이 처음부터 옳았던** 사례가 다수 발생.

이 패턴은 단순한 사실 오류 이상의 문제다. 에이전트가 "자신감 있는 추측"을 "검증된 사실"처럼 단정적으로 제시하기 때문에, 1차 자료를 가진 사용자가 오히려 자신의 정확한 직관을 의심하게 되는 역효과를 낳는다.

---

## 2. 재현된 구체적 사례

본 이슈는 `subscription-helper` 프로젝트 (한국 주택 청약 자격 분석) 대화에서 관찰되었다. 사용자의 개인 청약 자격/세대 정보는 본 문서에 기재하지 않으며, 청약 제도 일반론 수준에서만 사례를 정리한다.

### 사례 1: 부부 다건 청약 가능 여부

- **사용자 발언 (1차)**: "부부가 한 단지에 4건 신청해서 확률을 높일 수 있지 않냐?"
- **에이전트 1차 답변**: "안 됩니다. 세대당 1건이 원칙이므로 효과가 없습니다." (2차 자료/일반론 근거)
- **사용자 추가 push (2차)**: "정말이야? 다시 확인해봐."
- **에이전트 2차 답변**: 부분 수정 — "특별공급은 세대당 1건이지만 일반공급은 별도일 수 있습니다." (여전히 불완전)
- **사용자 3차 push**: "조사해봐."
- **deepresearch 호출 후 최종 정답**: 부부 동시 청약 특례(2024년 3월부터 시행)에 따라 **부부가 동일 단지의 일반공급에 각자 신청 가능**하며, 이 경우 4건까지 신청 가능. 사용자 직관이 옳았음.

### 사례 2: "후접수 추첨 박스 안 들어감" 박스 비유

- **사용자 발언**: 후접수자가 추첨 박스에 들어가지 않고 사전 배제될 가능성을 우려.
- **에이전트 1차 답변**: 추측 기반 박스 비유 — "후접수자는 추첨 박스에 들어가지 않고, 1차 추첨에서 떨어진 사람만 들어갑니다." (단정적 표현)
- **사용자 push**: "정말 그래?"
- **deepresearch 호출 후 정답**: 실제로는 **후접수자와 일반 접수자 모두 추첨에 함께 참여한 뒤 사후 정리**하는 방식. 박스 비유 자체가 사실과 다름. 단정적 추측이 사용자에게 잘못된 멘탈 모델을 심을 뻔함.

### 사례 3: 공공분양 일반공급 청약 가능 건수

- **사용자 발언**: "공공분양도 부부 동시에 가능한 거 맞아?"
- **에이전트 1차 답변**: "공공분양 일반공급은 세대당 1명만 가능하므로 최대 3장 한계입니다." (블로그 일반론 근거)
- **사용자 추가 push**: "정말? 공고문 확인했어?"
- **공고문 직접 확인 후 정답**: 부부 동시 청약 특례는 **민간/공공 구분 없이** 적용되어, 공공분양도 부부가 일반공급에 각자 1건씩 신청 가능. 최대 4장. 사용자 직관이 옳았음.

### 사례 4: 트랙 분산 전략 vs 몰빵 전략

- **에이전트 1차 권고**: "다자녀, 신혼부부 등 여러 특별공급 트랙으로 분산하여 신청하는 것이 안전합니다." (일반론적 위험분산 사고)
- **사용자 정정**: "큰 풀에 몰빵해야지, 분산하면 어디서도 안 돼."
- **재검토 후 정답**: 사용자가 가장 강한 가점을 가진 단일 트랙(신생아 특별공급)에 집중하는 것이 통계적으로 더 유리. 사용자의 도메인 직관이 에이전트의 일반론보다 정확.

## 3. 근본 원인 분석

### 3.1 검증 우선순위 잘못 설정

에이전트가 **일반론·블로그 표현을 법령 원문·공고문 명시 조항보다 우선시**하는 경향이 있다. 특히:

- 학습 데이터에 자주 등장하는 일반론(예: "청약은 세대당 1건")이 최근 제도 변경(예: 2024년 3월 부부 동시 청약 특례)보다 우선 활성화.
- 1차 자료(법령, 공고문)를 직접 확인하기보다 학습된 일반론으로 즉답.

### 3.2 사용자 직관을 정정 대상으로 처리

사용자가 반박하면 에이전트는 **"사용자가 틀렸을 가능성"부터 가정**하고 자신의 답변을 방어하는 패턴을 보인다. 이는 검증 후 결론이 아닌 반박이 먼저 나오는 형태로 나타난다.

### 3.3 deepresearch 호출 임계점 너무 높음

현재 `deepresearch` 스킬은 사용자가 명시적으로 "조사해봐", "찾아봐"라고 요청할 때만 호출된다. 사용자가 "정말?", "확실해?", "근거가 뭐야?" 같은 의심·검증 요구를 보내도 **자발적으로 deepresearch가 호출되지 않는다**.

### 3.4 자신감 보정 부재 (Overconfidence)

에이전트가 추측을 사실처럼 **단정적 어조**로 제시한다. 박스 비유 같은 비유 표현은 검증된 모델에만 사용되어야 하는데, 추측 단계에서도 비유가 사용되어 사용자가 잘못된 멘탈 모델을 형성하게 만든다.

### 3.5 메타 인지 부재

이전 대화에서 사용자 직관이 옳았던 사례가 학습 메모리에 기록되지 않아, 동일한 패턴이 반복된다.

## 4. 개선 제안

### 제안 1: 1차 자료 우선 원칙 명문화

**적용 위치 후보**:
- `.claude/agents/researcher.md`
- `.claude/skills/deepresearch/SKILL.md`
- `.claude/agents/orchestrator.md` (Verification Rules 섹션 확장)

**규칙 초안**:

```markdown
## Source Hierarchy (자료 우선순위)

사실 확인 시 다음 순서로 검증한다. 상위 등급이 하위 등급과 충돌하면 상위를 채택한다.

1. **Tier 1 (1차 자료)**: 법령 원문, 공식 공고문, 정부 부처 고시, 공식 API 응답, 1차 출판물
2. **Tier 2 (준 1차 자료)**: 공식 FAQ, 정부/기관 보도자료, 공식 사용자 매뉴얼
3. **Tier 3 (2차 자료)**: 신뢰할 만한 언론사 기사, 공인 전문가 블로그
4. **Tier 4 (참고)**: 일반 블로그, 커뮤니티 게시글, 학습 데이터의 일반론

- Tier 1을 확인하지 않은 채로 Tier 3/4에 근거하여 단정적 결론을 내려서는 안 된다.
- 사용자가 Tier 1 자료(공고문, 법령)를 직접 보고 있을 가능성이 있는 도메인(법률, 청약, 세무, 의료 등)에서는 반드시 Tier 1 확인 후 답변한다.
```

### 제안 2: 사용자 반박 트리거 강화

**적용 위치 후보**: `.claude/agents/orchestrator.md` (Adaptive Execution 섹션)

**규칙 초안**:

```markdown
## User Pushback Trigger (사용자 반박 자동 대응)

사용자가 직전 답변에 의심을 표하거나 검증을 요구할 때 — 다음 키워드/패턴 감지 시 **자동으로 deepresearch를 호출**한다:

- "정말?", "확실해?", "맞아?", "진짜?"
- "다시 확인해", "다시 조사해", "근거가 뭐야"
- "공고문 봤어?", "원문 확인해", "1차 자료 확인해"
- 같은 주장을 2회 연속 반복하는 경우 (직전 답변이 틀렸을 가능성을 가정)

자동 호출 시 행동:
1. 직전 답변을 "추정"으로 강등하고 사용자에게 알린다.
2. Tier 1 자료를 직접 인용하여 재검증한다.
3. 결과가 직전 답변과 다르면 명확히 정정한다.
```

### 제안 3: 단정적 표현 회피 (전 에이전트 공통)

**적용 위치 후보**: 신규 파일 `.claude/rules/epistemic-honesty.md` 또는 각 에이전트 정의에 인라인 추가

**규칙 초안**:

```markdown
## Epistemic Honesty (인식적 정직)

- 출처 명시 없이 "X는 Y다"로 단정하지 않는다. 대신 "공고문 N페이지에 따르면 Y", "법령 제N조에 따르면 Y" 형태로 출처를 동반한다.
- 추측은 반드시 "추정", "일반적으로", "확인 필요" 등으로 명시한다.
- 비유(박스, 항아리 등)는 검증된 모델에만 사용한다. 추측 단계에서 비유를 사용하면 사용자가 잘못된 멘탈 모델을 형성한다.
- 자신감 수준을 명시한다: "확실 (1차 자료 확인)", "추정 (일반론 기반)", "모름 (조사 필요)".
```

### 제안 4: 자기 검증 체크리스트 추가

**적용 위치 후보**: `.claude/agents/orchestrator.md`, `.claude/agents/researcher.md`

사용자 반박을 받았을 때 응답 전 점검:

```markdown
## Self-Check on Pushback (사용자 반박 시 자기 점검)

응답하기 전 반드시 확인:
1. 내가 인용한 근거는 Tier 1(1차 자료)인가, Tier 3/4(일반론)인가?
2. 본 도메인의 원본 문서(공고문, 법령, 공식 API 응답)를 직접 확인했는가?
3. 사용자 주장이 맞을 가능성을 진지하게 검토했는가? (즉시 반박 모드로 진입하지 않았는가)
4. 최근 제도/사양 변경 가능성을 검토했는가? (학습 데이터 시점 이후 변경)
5. 단정적 어조와 자신감이 실제 근거 수준에 비례하는가?

위 중 하나라도 No이면 답변 보류 → deepresearch 또는 1차 자료 조회 후 응답.
```

### 제안 5: 메타 인지 메모리 (Lessons Learned)

**적용 위치 후보**: `.claude/agent-memory/researcher/lessons-learned.md` 또는 `.claude/agent-memory/orchestrator/user-intuition-correct-cases.md`

사용자 직관이 옳았던 사례를 누적 기록하여, 동일 도메인에서 사용자 반박이 들어올 때 "이 사용자는 1차 자료를 보고 있을 가능성이 높다"는 사전 확률을 높인다.

**기록 항목 예시**:
- 도메인 (예: 한국 청약 제도)
- 사용자 주장
- 에이전트 초기 답변 (틀림)
- 최종 정답
- 교훈 (예: "2024년 이후 제도 변경은 학습 데이터에 미반영. 청약 도메인 답변 전 deepresearch 우선.")
